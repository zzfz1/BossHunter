# 应届生求职第二阶段

工作台的应届生岗位保留原岗位链接与“我已投递”。新增功能如下：

- **沟通草稿**：逐岗生成首次招呼语，或在用户提供沟通背景后生成后续消息。草稿可以编辑、复制；用户在平台或 App 内自行检查和发送。生成草稿需要已导入简历及可用的 AI 配置。BossHunter 不会借此调用任何平台消息接口。
- **管理简历**：打开应届生求职“我的简历”页面。用户在平台内自行填写、上传或管理简历；不会自动进行 51 简历同步或覆盖现有简历。
- **投递进度**：已投递岗位可打开应届生个人中心，用户人工核对后在工作台记下进度和下次检查日期。记录仅来源于用户输入，当前不自动读取平台投递状态或 HR 消息。
- **单岗位申请适配器**：后端包含“只读检查页面 → 返回短期岗位确认令牌 → 用户逐岗确认 → 仅点击一次立即申请 → 核对页面结果”的独立流程。它不进入 BOSS 的批量投递、招呼语发送或监控队列。外链岗位只支持打开原网站手动申请。

申请适配器的 `platforms.yingjiesheng.application_enabled` 默认是 `false`。真实登录态页面的按钮、登录、申请反馈与验证提示全部验收后，才能将其设为 `true`。启用后仍需在工作台逐岗点击“检查申请条件”和“确认并立即申请”；后端还会核对同源岗位 ID、页面职位、时间窗口、日额度、访问额度及账号安全锁。验证码、登录失效、限流、页面结构变化或结果不确定时停止，不自动重试。

验收期间不要用真实岗位点击确认申请，也不要发送真实消息。验证码和登录由用户在服务器 Chrome 里人工完成。测试使用模拟浏览器与脱敏岗位，不使用真实 Cookie、简历内容或第三方接口。
